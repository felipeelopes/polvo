Git no Polvo

Um gerenciador de git com tudo o que o GitHub Desktop faz, só que integrado aos projetos, worktrees e agentes do Polvo: você vê o diff do que o Claude está fazendo enquanto ele trabalha e faz commit sem sair da janela.

1 · Onde colocar

Três jeitos de encaixar o git no Polvo. A recomendação é a C: um painel lateral ao lado das sessões, que expande para tela cheia quando você precisa de espaço. Ela reaproveita o mecanismo do painel de documentos, que já existe.

A

Terceira visão: “Git”

Painéis · Quadro · Git

Um botão “Git” ao lado de Painéis e Quadro (Ctrl+Shift+3) troca a área central pela interface do GitHub Desktop.

  • Muito espaço, parece um app de git de verdade
  • Simples de entender
  • Esconde os agentes: não dá para ver o diff enquanto o Claude trabalha
B

Gaveta dentro da sessão

diff desta sessão

Cada painel de sessão ganha uma gaveta “Alterações” embaixo do terminal, com o diff da pasta daquela sessão.

  • O contexto é óbvio: é o git daquele chat
  • Pouco espaço; com muitos painéis fica apertado
  • Histórico, branches e PRs não cabem
C · recomendado

Painel lateral + tela cheia

⎇ main ↑2 · ⟳ Docs · Git

O painel da direita (o mesmo do visualizador de Markdown) ganha uma aba Git. Ele segue o projeto ou worktree em foco e expande para tela cheia.

  • Agente e diff lado a lado, ao vivo
  • Em tela cheia, vira o “GitHub Desktop” completo
  • Reaproveita o painel, as abas e o redimensionamento que já existem
  • Exige transformar o painel de documentos num painel genérico com abas

2 · Protótipo interativo (opção C)

3 · Pontos de entrada

O git aparece só onde ajuda e nunca atrapalha os agentes. Todos esses pontos levam ao mesmo painel, já filtrado no projeto ou worktree certo.

Barra de título

  • Chip de branch do projeto em foco: troca de branch, cria branch, busca com filtro, “Nova branch + sessão em worktree”.
  • Botão de sincronizar com estado: Buscar, Puxar ↓3, Enviar ↑2, Publicar branch. Mostra o progresso no próprio botão.
  • Só aparece quando a pasta em foco é um repositório git.

Barra lateral (projetos e worktrees)

  • Selos discretos: ●5 alterados, ↑2 para enviar, ↓3 para puxar, ⚠ em conflito.
  • Clicar no selo abre o painel Git naquele worktree.
  • Menu do worktree: Nova worktree…, Remover worktree, Abrir no Explorer.

Cabeçalho de cada sessão

  • Mostra branch e alterações da pasta da sessão (⎇ feat/x ●5); clicar abre o diff daquela pasta.
  • Ao terminar o trabalho (status “aguardando”), aparece uma dica: “5 arquivos alterados · Revisar e fazer commit”.

Teclado e terminal

  • Ctrl+Shift+G abre o painel Git · Ctrl+Enter faz o commit · Ctrl+Shift+P envia (push).
  • Ctrl + clique em qualquer arquivo no terminal (não só .md) abre o diff dele.
  • O Quadro mostra ●5 ↑2 nos cartões.

4 · Fluxos principais

Revisar e fazer commit do que o agente fez

1 · Agente terminaO painel mostra a dica “5 arquivos alterados”.
→
2 · RevisarPainel Git: lista à esquerda, diff à direita. Marque ou desmarque arquivos, trechos ou linhas.
→
3 · MensagemEscreva, ou use ✳ Gerar com Claude a partir do diff selecionado.
→
4 · CommitCtrl+Enter. A opção “Corrigir último commit” (amend) fica no menu ▾.
→
5 · EnviarO botão vira “Enviar ↑1”. Sem upstream, vira “Publicar branch”.

Trocar de branch com alterações

  • Diálogo como no GitHub Desktop: Deixar as alterações em main (guarda num stash ligado à branch) ou Levar as alterações para feat/x.
  • Se houver agente trabalhando naquela pasta, avisa antes: “O Claude está editando aqui. Trocar de branch agora pode confundir o chat.” Sugere abrir a branch numa worktree.

Conflitos (merge, rebase, cherry-pick, pull)

  • Faixa vermelha no painel: “Merge com conflitos em 3 arquivos”, com Abortar e Continuar.
  • Cada arquivo tem as opções: Usar a minha · Usar a deles · Abrir no editor · ✳ Pedir ao Claude para resolver.
  • Continuar só fica disponível quando não sobra nenhum marcador <<<<<<<.

Pull request

  • “Criar PR” a partir da branch: título e descrição (com ✳ Gerar), base, rascunho e revisores, usando gh.
  • A aba PRs mostra os PRs do repositório, o status do CI e os comentários de revisão. Fazer checkout de um PR abre uma worktree + sessão, se você quiser.

Histórico

  • Lista com grafo simples, tags e o marcador “não enviado”. Busca por mensagem, autor ou SHA.
  • Ações no commit: Reverter, Criar branch daqui, Criar tag, Cherry-pick para…, Resetar até aqui, Copiar SHA, Ver no GitHub.
  • Arrastar e soltar: arrastar um commit para uma branch faz cherry-pick; arrastar entre commits não enviados reordena ou junta (squash).
  • “Desfazer último commit” enquanto ele ainda não foi enviado.

5 · Integração com agentes (o diferencial)

É aqui que o Polvo passa a fazer o que o GitHub Desktop não faz. Cada ação de IA abre ou usa uma sessão visível, nunca algo escondido.

✳ Gerar mensagem

Usa claude -p (ou o agente preferido) sobre o diff selecionado e preenche o resumo e a descrição. Respeita o padrão de commits do repositório, lendo os últimos 20.

✳ Revisar diff

Abre uma sessão nova ao lado com o prompt “revise estas alterações”, pronta para conversar sobre os achados.

✳ Resolver conflito

Envia ao agente os arquivos em conflito e o contexto do merge; você revisa o resultado no diff antes de continuar.

Branch → worktree → sessão

“Nova branch numa worktree” cria ../polvo-feat-x, adiciona à barra lateral e inicia um agente ali. É o jeito certo de rodar vários agentes no mesmo repositório.

Quem mudou o quê

Arquivos alterados enquanto uma sessão estava “trabalhando” levam a etiqueta do agente (Claude). É uma inferência por horário, para saber de quem é cada mudança.

Ponto de restauração

Antes de enviar uma tarefa grande ao agente: “Criar ponto de restauração” faz um stash ou commit temporário, para desfazer tudo depois com um clique.

7 · Arquitetura

Backend: git pela linha de comando

  • Novo módulo src-tauri/src/gitops.rs que roda o git CLI, como o git.rs já faz. Assim ele usa a configuração, os hooks, o Credential Manager, a assinatura e o LFS do usuário, sem crescer o binário com libgit2.
  • Saída em formato de máquina: status --porcelain=v2 -z --branch, log -z --format=…, diff --no-color --patch.
  • Operações longas (fetch, pull, push, clone) com --progress, mandando o progresso por um Channel, igual ao pty_attach.
  • Uma fila de operações por repositório, para não haver duas escritas ao mesmo tempo. Leituras rodam em spawn_blocking.
  • GitHub via gh (já autenticado): PRs, checks e repositórios.
  • Avisos de mudança: polling leve do status (2 s no repositório visível, 30 s nos outros), mais uma atualização imediata ao focar a janela ou quando uma sessão muda de status.

Frontend

  • src/dock/: o painel de documentos vira um painel genérico com abas, que hospeda Docs e Git. A largura, a tela cheia e a persistência são as que já existem.
  • src/git/: panel.ts, changes.ts, diff.ts (reaproveita o highlight.js), history.ts, branches.ts, prs.ts, conflicts.ts, sync.ts.
  • O estado de git em store.git cresce para incluir status, ahead/behind e conflitos; os selos da barra lateral e da titlebar leem dali.
  • Carregado sob demanda, como o editor e o mermaid.
  • Testes em tests/ para os parsers (porcelain v2, log, diff/hunks) e para montar patches parciais.
